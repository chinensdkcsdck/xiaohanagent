# 医疗导诊与预约智能体系统｜项目介绍（AI核心版，含高并发亮点）


1. 客户端调用 /xiaohan/chat，经过 TraceIdFilter 注入 X-Trace-Id，经过登录拦截器校验会话。
2. 控制器进入编排服务，SkillMatcher 先匹配 skill，再路由到对应 agent。

5. Service 层执行并发控制（锁、查重、容量、事务），成功后返回业务结果；若启用 MQ，事务提交后异步发事件。
6. 返回响应，同时记录 chat/tool/rag/booking/exam 指标，日志可按 traceId 追踪整条请求。


高并发重点（你项目真正抗压的地方）

1. 先锁后查后写。                                                                                                                                                                                      
   tryBook/tryBookExam 都是先按“号源维度”加分布式锁，再做查重和容量判断，再入库，避免并发超卖。
2. 锁粒度是“槽位锁”。                                                                                                                                                                                  
   改约涉及旧槽位和新槽位，先对两个 lockKey 排序后再依次加锁，避免 A->B 与 B->A 相互等待。
4. 数据库唯一索引兜底。
   即使极端情况下锁失效，唯一索引还能拦住重复写入，保证最终一致性。
5. 事务边界清晰。
   预约/改约/检查写库都在事务里，失败回滚；MQ 事件采用 afterCommit 发布，避免“事务回滚但消息已发”。
6. 消费端幂等。
   你有 app.booking.*、app.exam.*、app.tool.*、app.chat.* 等指标，可快速区分“锁竞争高”“容量满”“DB慢”“工具慢”。

## 1. 项目定位
本项目核心是**AI 智能体（LLM + RAG + Tool Calling）**，目标是把医疗咨询从“能回答”升级到“能执行”。

系统主线：
1. AI 决策主线：理解用户诉求、匹配场景技能、补齐槽位、选择工具。
2. 业务执行主线：通过 `@Tool` 完成预约、改约、检查、报告解读等真实动作。

高并发治理定位：**工程保障亮点**，用于保证 AI 执行链路在高并发下依然正确稳定。

## 2. 技术栈（详细）

### 2.1 后端与框架
1. Java 17
2. Spring Boot 3.2.6
3. Spring Web + WebFlux（SSE）
4. Spring Validation / AOP / Actuator

### 2.2 AI 与检索增强
1. LangChain4j 1.0.0-beta3
2. DashScope Qwen Chat Model
3. `@AiService` 声明式编排
4. Tool Calling（`@Tool` + `@P`）
5. RAG（Embedding 检索）
6. Pinecone（可降级 InMemory）
7. MongoDB（会话记忆）

### 2.3 数据与中间件
1. MySQL + MyBatis-Plus
2. Flyway
3. Redis（分布式锁可选）
4. RabbitMQ（异步、重试、DLQ）

### 2.4 可观测性
1. Micrometer
2. TraceId
3. 统一错误码

## 3. AI 架构设计（核心）

### 3.1 Skills 决策大脑
1. `SkillRegistry`：加载 `resources/skills/*.yaml`。
2. `SkillMatcher`：按关键词/样例进行意图匹配。
3. `SkillOrchestratorService`：统一编排路由、风险兜底、槽位追问。
4. `ASK_SLOT`：预约场景缺 `科室/日期/时段` 时先追问再执行。

### 3.2 @Tool 执行层
1. `AppointmentSkillAgent -> AppointmentTools`
2. `AdvancedSkillAgent -> AdvancedMedicalTools`
3. `GeneralSkillAgent -> 通用问答`

### 3.3 RAG 与记忆层
1. MongoDB 持久化多轮记忆（`maxMessages=20`）
2. RAG 检索参数：`maxResults=3`、`minScore=0.75`
3. `ObservedContentRetriever` 指标化召回质量与时延

## 4. 我的核心工作（按优先级）
1. 设计并实现 `Skills + @Tool` 智能体分层架构（核心）。
2. 落地 `ASK_SLOT` 追问机制，提高工具调用有效率（核心）。
3. 打通 AI 决策到预约交易执行，形成可落地闭环（核心）。
4. 建设 AI 可观测指标：`app.rag.*`、`app.chat.*`、`app.skill.*`（核心）。
5. 补齐高并发治理：分布式锁、事务改约、幂等消费、DLQ（亮点）。

## 5. 高并发治理（亮点，不是主线）
1. 分布式锁抽象：MySQL `GET_LOCK` / Redis Redisson 双实现可切换。
2. 改约一致性：`@Transactional` + 固定顺序双锁 + 原子切换。
3. 防重复与防超卖：业务判重 + 唯一索引 + 容量校验。
4. 消息可靠性：事务后发布、幂等消费（`message_id` 唯一）、重试退避、DLQ 落库告警。
